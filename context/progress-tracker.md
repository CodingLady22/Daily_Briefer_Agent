> **Code review (post-4.2) — 6 issues found and fixed, all live-reverified.** New rules 13–16 added to `architecture.md` and the error-handling section of `code-standards.md` codify these permanently:
> 1. **Error double-counting** — `benchmark.agent.ts` and `webSearch.agent.ts` both returned `errors: [...state.errors, message]`, but the `errors` reducer in `state.ts` already appends (`(curr, next) => [...curr, ...next]`), so every prior error was being duplicated on every subsequent failure. Fixed: catch blocks and error-carrying returns now return only the NEW error(s) — `errors: [message]` — never spread `state.errors` back in. Codified as architecture.md rule 16 / code-standards.md's error-handling section (with an explicit ❌/✅ example).
> 2. **Snapshot guard** — `benchmark.agent.ts` now requires `currentScores.length >= MIN_SNAPSHOT_ITEMS` (5) before calling `BenchmarkSnapshot.create()`. Below that, the write is skipped, the previous snapshot stays the baseline, and `"Benchmark: low-yield extraction (N scores), snapshot not saved"` is pushed to `errors[]` — a bad scrape can no longer silently destroy the diff history. Codified as architecture.md rule 13 (applies to `PricingSnapshot` too — carry into 4.3).
> 3. **Dedupe before diff/save** — added `dedupeScores()` in `benchmark.agent.ts`: sorts by `source` then collapses to one row per `modelName::benchmark` key (last write after sort wins, deterministic), applied to `currentScores` before both `calculateDeltas` and the snapshot write. Prevents cross-citing sources (e.g. HELM quoting Arena numbers) from producing duplicate delta rows. Codified as architecture.md rule 14 (same `modelName::provider` pattern applies to Pricing in 4.3).
> 4. **Partial-data resilience** — `benchmarkScraper.tool.ts` switched from `Promise.all` to `Promise.allSettled` over its three leaderboard queries; a rejected query now logs `"benchmarkScraper: <query> failed - <reason>"` to a returned `errors[]` array instead of discarding the other two queries' successful results. Tool's return type changed from `RawItem[]` to `{ items: RawItem[]; errors: string[] }`. Codified as architecture.md rule 15.
> 5. **Dropped-URL visibility** — `search.tool.ts`'s return type changed from `RawItem[]` to `{ items: RawItem[]; droppedCount: number }` so the unparseable-URL count (see the bug above) is no longer silently discarded. Every caller (`webSearch.agent.ts`, `benchmarkScraper.tool.ts`) now logs `"search: skipped N unparseable URLs (<source>)"` to its own errors when `droppedCount > 0`. `pricingScraper.tool.ts` was updated only enough to compile (`(await search(...)).items`) since its agent doesn't exist yet — give it the same error-surfacing treatment when building 4.3.
> 6. **Token headroom** — `benchmark.agent.ts`'s `MAX_TOKENS` raised from 4096 to 8192, since live runs already extract 40-50+ scores in one structured-output pass. Comment left in place: if a parse ever fails on length, chunk the extraction rather than raising this indefinitely.
